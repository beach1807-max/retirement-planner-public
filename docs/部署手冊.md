# 公版部署位置、方式與架構交接手冊

本文件是 `retirement-planner-public` 的部署權威說明，供維護者與 AI agent 在修改、提交、推送及部署前後核對。最後更新：2026-09-16。

## 1. 版本與部署位置

| 項目 | 公版固定值 |
|---|---|
| 版本名稱／代號 | `公版`／`PUBLIC` |
| 本機工作目錄 | `T:\CODEX\retirement-planner-public` |
| GitHub repository | `https://github.com/beach1807-max/retirement-planner-public` |
| Git remote | `origin` → `https://github.com/beach1807-max/retirement-planner-public.git` |
| 目前驗收 Git 分支 | `preview` |
| Cloudflare Pages project | `retirement-planner-public` |
| 目前驗收部署分支 | `preview` |
| 固定驗收網址 | `https://preview.retirement-planner-public.pages.dev/` |
| Production 分支／根網址 | `main`／`https://retirement-planner-public.pages.dev/` |
| 部署整合方式 | Wrangler Direct Upload；Cloudflare 專案目前未連接 Git Provider |
| Node.js | `.nvmrc` 固定 `22.16.0` |
| 建置命令／輸出目錄 | `npm run build`／`dist` |

目前工作規則要求公版先部署及驗收 `preview`。除非使用者明確改變目標，維護者不得把 `main` 根網址當成 `preview` 驗收結果，也不得部署到私版專案 `retirement-planner-pwa`。

Cloudflare 每次部署會產生一個不可變的 deployment URL，例如 `<hash>.retirement-planner-public.pages.dev`；`preview.retirement-planner-public.pages.dev` 是分支別名，應指向 `preview` 最新 deployment。雜湊網址每次不同，不應寫死在程式或操作手冊中。

## 2. 部署資料流

```text
本機 PUBLIC repository（preview branch）
        │
        ├─ npm run check / npm run test:e2e
        ├─ git commit + git push origin preview
        │
        └─ npm run deploy
             ├─ tsc -b
             ├─ vite build
             ├─ 產生 dist、PWA Service Worker、build-version.json
             ├─ Wrangler Direct Upload
             │    project = retirement-planner-public
             │    branch  = preview
             └─ 列出 Pages deployments 供人工核對
                       │
                       ├─ 唯一 deployment URL
                       └─ https://preview.retirement-planner-public.pages.dev/
```

GitHub push 與 Cloudflare upload 是兩個獨立步驟。因 Cloudflare Pages 專案目前的 `Git Provider` 為 `No`，只 push GitHub 不會自動更新網站；必須執行 Wrangler Direct Upload。

## 3. 應用與執行架構

### 瀏覽器端

- React 19 + TypeScript + Vite 靜態應用。
- `src/domain/`：純領域與金融計算；金額及利率計算使用 `decimal.js`。
- `src/application/`：規劃、情境、快速新增、行情同步與資料遷移等應用服務。
- `src/infrastructure/`：Dexie repository、備份格式、行情 provider 與路由。
- `src/components/`：UI，包括 `CurrencyInput`、`DemoBanner`、Dashboard、資料與負債管理。
- 使用者財務資料只存於瀏覽器 IndexedDB；不得傳送到後端或寫入 repository。

### PWA 與版本辨識

- `vite-plugin-pwa` 產生 `sw.js` 與 Web App Manifest。
- Service Worker 採 `registerType: prompt`，有新版時由 UI 提示使用者更新。
- `vite.config.ts` 在建置時產生 `dist/build-version.json`，內容包含：
  - `project: retirement-planner-public`
  - `version: PUBLIC`
  - 建置時的 Git `commit`
  - 建置時的 Git `branch`
- 驗證部署不得只看畫面，必須回讀 `/build-version.json`。

### Cloudflare Pages 與 Functions

- `dist/` 是 Pages 靜態資產來源。
- `functions/api/market-data.js` 會隨 Direct Upload 一併發布為 Pages Function，提供 `/api/market-data` 行情／匯率代理。
- 瀏覽器端另有行情 provider 與備援路由；任何擴充都必須保持「不傳送持有數量、資產金額或家庭資料」的隱私界線。
- `wrangler.jsonc` 的 `name` 必須保持 `retirement-planner-public`，`pages_build_output_dir` 必須保持 `./dist`。

## 4. 安全部署標準流程

### 4.1 部署前必要核對

```powershell
Get-Location
git remote -v
git branch --show-current
git rev-parse HEAD
git status --short --branch
npx wrangler whoami
```

必須同時成立：

1. 目錄是 `T:\CODEX\retirement-planner-public`。
2. `origin` 是 `beach1807-max/retirement-planner-public`。
3. branch 是 `preview`。
4. 工作樹沒有未說明的修改；既存使用者檔案不得擅自納入提交。
5. Cloudflare 目標是 `retirement-planner-public`，不是 `retirement-planner-pwa`。

### 4.2 測試、提交與推送

```powershell
npm ci
npm run check
npm run test:e2e
git status --short
git add <本次明確修改的檔案>
git commit -m "【公版修正】<說明>"
git push origin preview
```

`npm run check` 依序執行 ESLint、Vitest、TypeScript 與 Vite production build。任何檢查失敗都不得部署。

### 4.3 部署

```powershell
npm run deploy
```

`package.json` 已把預設部署鎖定成：

```text
npm run build
wrangler pages deploy dist --project-name retirement-planner-public --branch preview
wrangler pages deployment list --project-name retirement-planner-public
```

不要改用未指定 `--branch preview` 的 `wrangler pages deploy dist`；該做法曾將公版 UI commit `7a15667` 誤部署成 `main / Production`，使固定 `preview` 驗收網址仍停留在舊 commit。

## 5. 部署後必驗項目

### 5.1 核對 deployment 記錄

```powershell
npx wrangler pages deployment list --project-name retirement-planner-public
```

最新一筆必須符合：

- Project：`retirement-planner-public`
- Environment：`Preview`
- Branch：`preview`
- Source：等於剛推送的 `preview` commit 短雜湊
- Deployment URL：可正常回應

### 5.2 回讀線上建置版本

```powershell
$expected = git rev-parse HEAD
$actual = Invoke-RestMethod 'https://preview.retirement-planner-public.pages.dev/build-version.json'
$actual
if ($actual.project -ne 'retirement-planner-public' -or
    $actual.version -ne 'PUBLIC' -or
    $actual.branch -ne 'preview' -or
    $actual.commit -ne $expected) {
  throw 'PUBLIC preview deployment verification failed.'
}
```

接著檢查：

- 首頁可載入，靜態 JS/CSS 無 404。
- `/api/market-data` Function 可回應，且不接受／傳送使用者財務資料。
- `build-version.json` 的 project、version、branch、commit 全部一致。
- 新功能的實際操作路徑可見，不只確認首頁文字。

若 deployment 記錄與 `build-version.json` 一致，但瀏覽器仍顯示舊版，先用無痕視窗驗證，再到瀏覽器開發工具的 Application／Service Workers 執行 unregister 與 Clear site data。不要在未核對版本檔前把所有問題歸因於快取。

## 6. Git 與 Cloudflare 分支角色

| 分支 | 角色 | Pages URL | 目前操作規則 |
|---|---|---|---|
| `preview` | 公版驗收 | `https://preview.retirement-planner-public.pages.dev/` | 目前唯一指定部署目標 |
| `main` | Cloudflare Production environment | `https://retirement-planner-public.pages.dev/` | 未經明確指示不得用來代替 preview 驗收 |

若功能先出現在 `main`、但必須於 `preview` 驗收，應正常 merge 或 cherry-pick 到 `preview`，保留分支歷史；禁止用 `git reset --hard` 加 `git push --force` 搬動共用分支。

## 7. 安全復原

優先使用可追蹤的 Git revert，不改寫遠端歷史：

```powershell
git switch preview
git pull --ff-only origin preview
git revert <造成問題的普通 commit>
# 若要撤銷 merge commit：git revert -m 1 <merge-commit>
npm run check
npm run test:e2e
git push origin preview
npm run deploy
```

安全基準 tag `v0.1.0-pre-ui-enhancement` 指向 `e8aa47377e7e0f33a2d3770746afb331b103bdad`，可用於比較或建立復原 commit，但不得直接 reset 後 force-push 共用分支。Cloudflare 的舊 deployment URL 可作比對，不等於 Git 已完成復原。

## 8. AI Agent 接手檢查清單

1. 先讀 repository 根目錄 `AGENTS.md`，一律使用中文。
2. 明確說出目標是 `PUBLIC`，不得把私版 repository 或 Pages project 當作公版。
3. 在任何寫入前回報目錄、remote、branch、commit、Pages project、部署分支與最終網址。
4. 保留不屬於任務的 dirty／untracked 檔案。
5. 不使用含糊的「正式版／預覽版」稱呼；使用 `公版`、`PUBLIC`、`preview`、`main`。
6. 先測試，再 commit、push，最後 Direct Upload。
7. 部署後同時核對 Wrangler deployment 清單與 `build-version.json`。
8. 回報唯一 deployment URL、固定 preview URL、source commit 與驗證結果。
