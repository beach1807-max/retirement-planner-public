# GitHub 與 Cloudflare Pages 部署手冊

## 已固定設定

| 項目 | 值 |
|---|---|
| Node.js | `22.16.0` |
| 建置命令 | `npm run build` |
| 輸出目錄 | `dist` |
| Cloudflare Pages 專案 | `retirement-planner-pwa` |
| 正式分支 | `main` |
| 正式網址 | `https://retirement-planner-pwa.pages.dev` |
| GitHub | `https://github.com/beach1807-max/retirement-planner-pwa` |

## 本機部署前

```bash
npm ci
npm run check
npm run test:e2e
```

## 直接部署至 Cloudflare Pages

```bash
npm run build
npm run deploy
```

Wrangler 4.127.1 的 `wrangler pages deploy` 沒有 `--dry-run` 參數，因此部署前以本機完整檢查、預覽分支及線上回讀取代。

## Cloudflare Git 自動部署（選配手動設定）

若要每次推送 GitHub 自動部署，可在 Cloudflare 控制台建立或連接 Git 整合：

1. Workers & Pages → Create application → Pages → Import an existing Git repository。
2. 選擇 GitHub 儲存庫及 `main` 分支。
3. Build command 設為 `npm run build`。
4. Build output directory 設為 `dist`。
5. Node.js 由儲存庫 `.nvmrc` 固定為 `22.16.0`。

若 Pages 專案是由 Direct Upload 建立，控制台是否允許改接 Git 依當時 Cloudflare 功能為準；無法切換時，可另建 Git-integrated Pages 專案或使用 GitHub Actions 配合 Cloudflare API Token。

## 使用者手動操作

- 在支援的瀏覽器開啟正式網址後，使用瀏覽器的「安裝應用程式／加入主畫面」。
- 第一次使用建立家庭資料，或先載入展示資料。
- 真實使用前刪除展示資料並重新建立自己的規劃。
- 定期到「備份還原」匯出 JSON 並存放於安全位置。
- 不要把含真實財務資料的 JSON 上傳到 GitHub Issue、公開雲端空間或客服訊息。
