# 階段一：契約、資料語意與遷移基線實作計畫

## 摘要

階段一只補正現有垂直切片的資料契約、應用服務邊界、輸入完整性與儲存版本，不實作勞保公式、行情 Provider、完整財務模型或新退休算法。

已鎖定決策：

- 完整第一版須正式估算勞保／勞退，規則採版本化且不得覆寫歷史版本；實作留在階段四。
- 手動更新股票、ETF、匯率是完整第一版必做；Provider 實作留在階段七。
- 退休計算維持 `calculation-contract-v0.1`，第一版不增加其他退休達標或生活費算法。
- Dashboard 退休結果固定代表「主要規劃人的家庭退休計畫」；家庭／個人切換只改變資產及完整度摘要。
- 退休目標與準備率以主要規劃人的「預計退休月份」為基準，採同一時間軸反推最低所需資產；實際計算留在階段三。
- IndexedDB 維持單一家庭聚合快照；規則及行情快取未來可另建資料表。
- 儲存模型先支援 ISO 幣別與原幣金額；階段一 UI 只接受 TWD，外幣沒有有效匯率時不得進入計算。
- 共同資產持分必須由使用者輸入且合計等於 100%。
- 目前沒有正式使用者舊資料；仍建立 v0.1→v0.2 遷移測試，但不設計舊 50／50 持分確認流程。

## 實作變更

### 1. 決策與版本契約

- 新增階段一決策紀錄，固定上述產品語意，並明確區分「垂直切片 v0.1」與「完整第一版」。
- `calculation-contract-v0.1` 的公式、事件順序、輸入雜湊與結果保持不變。
- Planner schema 升為 `planner-data-v0.2`，JSON 備份升為 `retirement-planner-backup-v0.2`。
- v0.2 匯出只產生新格式；匯入同時接受 v0.1、v0.2，v0.1 先遷移再驗證及儲存。
- 預留 `ruleVersion`、Market Data Provider 與退休模式識別欄位，但階段一不新增法規或行情實作。

### 2. 資料模型

將「持久化規劃資料」與「計算契約輸入」分離：

- 持久化模型使用 `PlannerAsset`、`PlannerContribution`；計算層保留 v0.1 所需的 TWD Asset／Contribution。
- 新增共用型別：
  - `MoneyAmount { amount: string; currency: string }`
  - `EntityTimestamps { createdAt: string; updatedAt: string }`
- `currency` 必須是三碼大寫 ISO 幣別；金額維持十進位字串。
- Household、Member、Asset、Contribution 都加入逐筆 `createdAt`、`updatedAt`。
- Asset 以 `currentValue: MoneyAmount` 取代持久化層的 `currentValueTwd`；CalculationInput 仍由應用服務產生 `currentValueTwd`。
- Contribution 以 `amount: MoneyAmount` 取代持久化層的 `amountTwd`。
- 主要規劃人的 `plannedRetirementMonth` 為應用層必填；伴侶只有在投入採 `ownerRetirement` 時才必填。
- 共同資產必須具備至少兩位有效家庭成員、成員不得重複、每筆持分大於 0，合計必須等於 1。
- individual 資產只能有 `ownerMemberId`；joint 只能有 `owners`；household 兩者皆不得保存。

### 3. 應用服務與資料流

新增單一 `PlannerService` 作為 UI 的入口：

- 負責載入、遷移、驗證、儲存、清除、備份還原及呼叫退休計算。
- 透過依賴注入取得 `PlannerRepository`，App 不再直接操作 Dexie Repository。
- 由 `toCalculationInputV01()` 將 PlannerData 轉換成既有 CalculationInput。
- 階段一只轉換 TWD；遇到非 TWD 且沒有後續匯率估值資料時回傳 `FX_RATE_REQUIRED`，不得默認 1：1。
- 建立 `DashboardViewModel`，集中計算範圍資產、共同持分及顯示標籤；Dashboard 不再自行篩選或使用 JavaScript `Number` 加總財務金額。
- 個人範圍只改變目前資產與資料完整度；退休年齡、退休時資產及時間軸維持家庭結果，畫面固定標示其語意。

資料流固定為：

```text
UI
→ PlannerService
→ 驗證／CalculationInput Adapter／Dashboard View Model
→ Calculation Engine 或 PlannerRepository
→ IndexedDB Adapter
```

### 4. 儲存與遷移

- IndexedDB 升為 version 2，仍使用單一 `current` 聚合紀錄並在 transaction 中完成遷移。
- v0.1 Asset：
  - `currentValueTwd` 遷移為 `{ amount: currentValueTwd, currency: "TWD" }`
  - 缺少的逐筆時間戳使用原 PlannerData `updatedAt`
- v0.1 Contribution：
  - `amountTwd` 遷移為 `{ amount: amountTwd, currency: "TWD" }`
  - 缺少的逐筆時間戳使用原 PlannerData `updatedAt`
- Household、Member 缺少的時間戳同樣使用根資料 `updatedAt`。
- 遷移不得使用目前時間填補舊資料，以確保同一份輸入可重現相同結果。
- 備份匯入流程為「解析版本 → 遷移 → 完整驗證 → 原子儲存」；任何步驟失敗均保留現有資料。
- 現階段不拆成多張實體資料表；行情快取及法規規則庫留待對應階段獨立建表。

### 5. UI 補齊

- Onboarding 新增主要規劃人的預計退休月份。
- 成員資料可編輯；伴侶可補填預計退休月份。
- Asset 支援完整新增與編輯：
  - 名稱、類型、TWD 金額、所有權、共同持分
  - 是否納入總資產、退休使用範圍、可動用日期
  - Return Profile、資料狀態
- Contribution 支援完整新增與編輯：
  - 來源成員、TWD 金額、使用範圍、開始日
  - `ownerRetirement`、`primaryRetirement`、`fixedDate`、`planEnd`
  - `fixedDate` 必填結束日
  - 目的資產或 Return Profile 二選一
- 共同持分未達或超過 100% 時阻止儲存並顯示欄位錯誤。
- 伴侶投入採本人退休停止但缺少退休月份時，提供直接前往補填的修正路徑。
- Dashboard 明示「退休結果為主要規劃人的家庭計畫」，切換範圍時該結果不得改變。

## 後續契約紀錄

階段一只固定、暫不實作下列規則：

- 勞保／勞退規則未來使用獨立版本包，至少保存版本、生效日、來源與查核日；新規則新增版本，不修改舊版本。
- 退休目標資產將在階段三以預計退休月份的資產配置為基礎，維持各資產比例，反推剛好滿足 v0.1 終點條件的最低資產。
- 準備率為「預計退休月份的預估可退休資產 ÷ 同月份退休目標資產 × 100%」，預設顯示實質金額。
- 目標資產為 0 時不顯示無限百分比，改顯示「已達標」。
- 預計退休月份不得早於計算基準月份或晚於規劃終點。

## 測試與驗收

- 既有 17 項單元／整合測試及 PWA E2E 持續通過。
- 相同 TWD 資料轉成 v0.2 後，`calculation-contract-v0.1` 的 input hash 與計算結果保持一致。
- IndexedDB v1 資料可在 transaction 中升級為 v2；重開應用後資料一致。
- Backup v0.1 可匯入並轉成 v0.2；v0.2 可匯出、還原並重現計算結果。
- 無效備份、失敗遷移或無效關聯不得覆蓋現有 IndexedDB。
- 測試 individual、joint、household 三種所有權及共同持分 99%、100%、101%、重複成員、非家庭成員案例。
- 測試四種投入停止規則、固定日期缺漏、結束日早於開始日及伴侶退休月份缺漏。
- 測試非 TWD 資產在無有效匯率時阻止 CalculationInput 組裝。
- E2E 覆蓋資產編輯、共同持分、投入固定停止日、伴侶退休月份修正及三種 Dashboard 範圍。
- 切換 Dashboard 範圍後，資產摘要依持分改變，但家庭退休結果及時間軸保持一致。
- `npm run check`、E2E、正式建置及離線重新開啟全部通過。
- Git 工作樹不得包含勞保公式、行情 API、Scenario、負債或其他階段功能。

## 假設與邊界

- 階段一沒有需要保留的正式使用者資料，但遷移仍作為未來 schema 演進範本。
- UI 暫時只開放 TWD；資料模型現在就支援其他 ISO 幣別，避免行情階段再次改變核心欄位。
- 不新增雲端資料庫、帳號、同步、稅務、交易、投資建議或自動行情。
- 不改變 v0.1 退休公式；任何會影響月份事件順序或退休成功定義的需求必須另建契約版本。
