# ADR 0003：完整第一版發布與階段一契約

日期：2026-09-02  
狀態：已接受

## 背景

既有垂直切片 v0.1 可完成基本退休試算，但主計畫所稱的完整第一版尚包含退休制度、投資組合、情境與手動行情等模組。為避免同一數字出現多種語意，先鎖定以下決策。

## 決策

| 編號 | 決策 |
|---|---|
| C-01 | 完整第一版必須正式估算勞保與勞退；規則使用不可覆寫的版本包，於階段四實作。 |
| C-02 | 手動更新股票、ETF 與匯率是完整第一版必做；Provider 於階段七實作。 |
| C-03 | 第一版只提供 `calculation-contract-v0.1` 的「支應至終點＋準備金＋遺產目標」與固定實質生活費模式。 |
| C-04 | Dashboard 的家庭／個人切換只影響資產與完整度摘要；退休結果永遠代表主要規劃人的家庭退休計畫。 |
| C-05 | Dashboard 只呈現 Planner Service 產生的 View Model，不自行承擔財務加總規則。 |
| C-06 | UI 一律經由 Planner Service 協調驗證、計算與 Repository；維持 React、Dexie 與既有計算引擎。 |
| C-07 | Planner schema 升為 `planner-data-v0.2`，金額保存原幣值與 ISO 幣別，實體保存建立／更新時間。舊 TWD 資料無損遷移為 TWD。 |
| C-08 | 共同持分由使用者明確輸入，至少兩位有效家庭成員且合計須為 100%。目前沒有正式舊資料，不另設舊 50／50 確認流程。 |
| C-09 | 文件與發布名稱區分「垂直切片 v0.1」與「主計畫完整第一版」。 |
| C-10 | 退休目標以主要規劃人的預計退休月份為基準，沿用相同資產配置反推最低所需資產；準備率為預估可退休資產除以目標資產。公式於階段三加入新 Projection 契約，既有 v0.1 保持可重現。 |

## 版本與遷移

- 計算契約維持 `calculation-contract-v0.1`，事件順序與成功條件不變。
- 持久化資料為 `planner-data-v0.2`；備份為 `retirement-planner-backup-v0.2`。
- 匯入接受 v0.1 與 v0.2；流程固定為解析版本、遷移、完整驗證、單次原子儲存。
- IndexedDB version 2 仍保存單一 `current` 家庭聚合快照，並在升級 transaction 中遷移。
- 缺少時間戳的 v0.1 實體使用根資料原有 `updatedAt`，不得使用遷移當下時間。
- 階段一 UI 只輸入 TWD；非 TWD 且沒有有效匯率時回傳 `FX_RATE_REQUIRED`，不得假設 1：1。

## 資料流

```text
UI → PlannerService → 驗證／v0.1 Adapter／Dashboard View Model
                  ├→ Calculation Engine
                  └→ PlannerRepository → IndexedDB Adapter
```

## 後果

完整第一版發布須完成七階段；後續法規、行情與 Projection 均以新版本或 Provider 擴充，不改寫既有結果所引用的契約與規則版本。
